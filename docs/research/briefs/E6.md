## 0. What the screening agents do

`scripts/research/specs/e6-<family>.json`, run `npx prettier --write` on it, then

```
npm run research:sim scripts/research/specs/e6-<family>.json -- --sessions 2000 --out docs/research/results/e6-<family>-screen.json
```

| family | spec file | experiments (incl. control) |
| --- | --- | --: |
| (a) widening, equal stake per covered number | `e6-widen.json` | 10 |
| (b) stacking at fixed coverage | `e6-stack.json` | 12 |
| (c) hybrid: widen, then stack | `e6-hybrid.json` | 11 |
| (d) cash-out and trailing stop on the best of (a) to (c) | `e6-cashout.json` | 12 |

The defaults already set the screening run: 2,000 sessions, seed 20261031 (the reporting seed for
screening), $5,000 bankroll, 500 spins, European wheel. Holdout seeds 1 and 2 come later at full size.
Every spec starts with the `flat-red` control on the same seed.

What to report back per experiment: mean, median, P(win), **cap rate**, CVaR 5 %, realized vs
analytic edge, wager/spin, and the predicted columns of this file beside them; then the top two by
median. Three things to know when reading the report:

- **`bust` reads 0.0 % on every ladder, by design.** Every ladder uses `onCap: 'stop'` and a cap loss
  that is below $5,000, so a lost ladder ends the session with `endedBy: "strategy:cap-q"` and the
  loss of the whole ladder, never with a bust. The cap rate is `endedBy["strategy:cap-q"] / N`; it is
  the number to compare with 1 − P(no cap@500).
- **`rejected` / `adjusted` are not in the runner's report** (`run.ts` does not export those summary
  columns). The smoke run in §7 read them from the harness directly: zero for every experiment. If
  the T2/T4 tooling has added them by the time you run, report any non-zero count; a non-zero count
  means the ladder did not run as designed.
- The `meta` block on each experiment (`{ c, p, B, q }`, for the T4 aggregator) is ignored by the
  runner. Its values: **c = first-level coverage c₀; p = p_eff, the effective win (cycle-completion)
  rate per spin; B = cap loss / τ̄ in mean cycle profits (effective); q = cycle cap probability
  Π(1 − p_k)**. With these, the aggregator's x = p·S/B is the x of this file.

## 1. The H3 expectation, stated plainly

E6 will not find a positive mean: EV per dollar is −2.70 % for every layout, and every row's model
mean is negative, from about −$55 (the smallest cash-out targets) to about −$640. The honest goal of E6 is to **test whether
any widening or stacking layout beats the H3 curve P(no cap by S) ≈ e^(−x), x = p_eff·S/B**. The
cycle model says none can: by the edge identity of §2, P(no cap) = e^(−x·qB/(1−q)) with qB/(1−q) ≥ 1,
so e^(−x) is a ceiling. A layout can only fall below it, by the factor
qB/(1 − q) = 1 + 0.027·E[wager per cycle]/(τ̄·(1 − q)) in the exponent, and the widening levels with large coverage make that factor large (a7:
qB = 1.57). The expected result is that every candidate sits on or below e^(−x), none above it by
more than sampling error (±2.2 points on P at 2,000 sessions), and that medians are set by x and the
bankroll actually committed (median ≈ x·cap loss while P(no cap) > ½), not by the arrangement of
numbers. A candidate that beats the curve by more than a few percent is a finding to re-run on the
holdouts, and a positive mean is a bug or a fluke.

**Compare the cap rate, not P(ahead), with the curve.** The curve is about P(no cap). For ladders
whose cap loss is small next to what 500 spins of cycles earn (a5, a6, a8, a9, b11, c6), many
sessions cap late and still finish ahead, so P(ahead at 500) ≈ 0.3 sits *above* e^(−x) (0.004 to
0.25) without beating anything. For those rows use 1 − cap rate against e^(−x) and e^(−λ).

## 2. Common design

**Reading of "constant stake per number".** Taken literally (the same dollars per number at every
level, more numbers deeper), a widening ladder cannot recover: a hit at level k nets
s·(36 − c_k) − D_k, which is 12s − 12s = 0 already at dozen → two dozens. So family (a) means an
*equal stake on every covered number within a level*, so that every covered number pays the same and
the recursion's "smallest payout" is every payout; the stake per number grows from level to level as
the recursion demands. Families (b) and (c) use the same rule. All pieces of a layout are disjoint
(no number is covered twice), and the piece amounts are in the ratio of their sizes (dozen : six-line :
street : split : straight = 12 : 6 : 3 : 2 : 1 per number), so the progression amount is the stake of
the smallest piece and larger pieces use `{ "times": [{ "prog": "q" }, m] }`.

**The deficit recursion.** τ is the net of a level-0 hit (the target profit per cycle). At level k
with coverage c_k, after a cumulative loss D_k in this cycle, the stake per number s_k is the
smallest chip-legal amount with 36·s_k − c_k·s_k − D_k ≥ τ, and D_{k+1} = D_k + c_k·s_k. Without
rounding this gives (D_{k+1} + τ) = (D_k + τ)·36/(36 − c_k), so a ladder of L levels loses
τ·(Π_k 36/(36 − c_k) − 1) when it caps, and caps with probability q = Π_k (1 − c_k/37). Chip rounding
($1 per inside chip and per outside bet) makes most levels net a little more than τ; the tables
carry the exact values. L is the largest level count whose cumulative stake fits $5,000. The bankroll, not the table
maximum, is what binds: the largest single spots in any candidate are a straight-up at $133 (a4,
limit $500), a split at $162 (a3, limit $1,000), a street at $412 (b1, limit $1,500), a corner at
$551 (b2, limit $2,000), a six-line at $783 (c2, limit $3,000) and an outside bet at $1,600 (b11,
limit $5,000).

**Tables.** Two rule sets:

- *default*: the high-limit table ($25 outside minimum, $25 inside minimum total).
- *low-min*: `{ "preset": "european", "overrides": { "limits": { "outside": { "min": 100 }, "inside": { "minTotal": 100 } } } }`,
  minima lowered to the $1 chip, maxima unchanged (same kind of override as E3a's lowered outside
  minimum).

The default table is not a usable lab for this question: τ ≥ $25·(36 − c₀)/c₀ for an equal-weight
first level (street $275, six-line $125, corner $200), so B ≤ $5,000/τ is tiny and every ladder has
λ ≫ 1. Each of (a), (b), (c) carries one default-table candidate as the reference (a9, b11, c6); all
others use low-min.

**Caps.** `onCap: 'stop'` everywhere: the ladder is bankroll-limited, the session ends at the first
lost ladder with the cap loss, and the cap loss is below the bankroll so a cap never busts. `reset`
was not used because after a cap the next ladder would not fit the remaining cash and reconcile would
reduce stakes (non-zero `adjusted`), which is a different strategy.

**Quantities in the tables.**

| symbol | definition |
| --- | --- |
| p_k | c_k / 37, the chance level k wins |
| q | Π_k (1 − p_k), the chance a cycle caps |
| E[len] | Σ_k Π_{j<k} (1 − p_j), the mean cycle length in spins |
| p_eff | (1 − q) / E[len], winning cycles per spin (= p for a single-coverage ladder) |
| τ, τ̄ | the level-0 net; the mean net of a winning cycle (τ̄ ≥ τ because of chip rounding) |
| cap loss, B | D_L, lost when a cycle caps; B = cap loss / τ̄ |
| x | p_eff·S / B, with S = 500 |
| λ | S·q / E[len], expected caps in 500 spins; λ = x·qB/(1 − q) |
| P(no cap@500) | e^(−λ) |
| H3 median@500 | τ̄·p_eff·S if e^(−λ) ≥ ½, else τ̄·p_eff·n½ − cap loss with n½ = ln2·E[len]/q (the median session is then the one that capped at n½) |
| qB | (1 − q) + 0.027·E[wager per cycle]/τ̄, exactly (the cycle's EV identity); the table prints it |
| model | the same ladder, the same stop rules, 20,000 sessions on an independent RNG (a cycle-model Monte Carlo, not the engine): the sharper prediction of median, P(win), mean |

P(win) is not P(no cap): a ladder with a small cap loss can cap late and still finish ahead (a5, a6,
a8, a9, b11, c6 have model P(win) ≈ 0.3 against P(no cap) < 0.2). The H3 median is a few percent
above the model median for long cycles (b1, b2) because the session that ends mid-cycle carries its
deficit; use the model column as the prediction to beat.

## 3. Family (a): widening at an equal stake per covered number

amount to recover by 36/(36 − c_k), which is ×1.09 at c = 3 but ×3 at 24 and ×6 at 30, and the $1
chip fixes τ ≥ $11 for a $1 street (τ = $35 for a $1 straight-up). The best path found (a1, one
street per level from 3 to 27 numbers) reaches λ = 0.60; every other path has λ ≥ 0.8, so only a1 is
predicted to finish 500 spins with a positive median, and narrowly (P(no cap) = 0.55).

## 5. Family (c): hybrid, widen until coverage 24, then stack

widening there is room for only one to three stacked levels, and the four "to 24" ladders (c1 to c4)

## 6. Family (d): cash-out at W cycles and a trailing stop

Base ladders: the best-predicted candidate of each family, by predicted median with P(no cap) ≥ ½:
**a1** (`a1-streets-w27`), **b1** (`b1-street-l53`), **c8** (`c8-sixlines-to18-stack`). Each gets
fixed targets (`session.stopWin` = W·τ) and the R16 trailing stop. The ladder JSON is unchanged.

**Trailing stop on a ladder.** Net at cycle boundaries only rises (every completed cycle adds at least
τ, and a cap ends the session), so a trailing stop measured on net can only fire *inside* a cycle,
when the running deficit reaches δ. With δ = D_j, the deficit after j straight losses, the R16 rules
(arm once at net ≥ A, lock = best net − δ, stop when net ≤ lock) mean: once ahead by A, abandon any
cycle that loses j times in a row and walk away with best net − D_j, instead of risking the rest of
the ladder. A is set to D_j + 10 to 40 τ so that a trailing stop always ends ahead. The rules are
R16 verbatim with A and δ in cents (the `vars`, `rules` keys of the trailing experiments).

**Prediction.** Banking M needs about M/τ̄ winning cycles, and each cycle caps with probability q,
so any exit rule on a ladder lies on the frontier P(win) ≲ (1 − q)^(M/τ̄) ≈ e^(−qM/τ̄): a fixed target
reaches it exactly (median = target while P(win) > ½), and the trailing stop is expected to land on
the same frontier, not above it (the model agrees within a point). The mean stays at −0.027 × wager
and is smaller in size only because sessions are shorter.
