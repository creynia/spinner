# Static pages, sitemap and llms files (SEO)

The app uses hash routes (`#/analyze/<id>`), which search engines and LLM crawlers ignore. So the
normal build (`npm run build`, i.e. `dist/`) also writes plain, JS-free HTML pages at real paths,
each with a link into the app. They are generated by `build/static-pages.ts` (the
`spinner-static-pages` Vite plugin, build only; the dev server does not serve them).

| Path (under `https://creynia.com/spinner/`) | What |
| --- | --- |
| `strategies/` | All gallery runs side by side, the house-edge explanation, CTA to `#/gallery` |
| `strategies/<slug>/` | One per gallery bundle (`<slug>` = file name minus `.spinner.json.gz`), in `gallery/order.json` order |
| `sitemap.xml` | The SPA root and every page above, absolute URLs, no `lastmod` |
| `llms.txt` | [llmstxt.org](https://llmstxt.org/) index of the app and the pages |
| `llms-full.txt` | The full text of every page as Markdown |

## Where the numbers come from

Nothing on a strategy page is typed in by hand. The plugin decodes each committed gallery bundle
(`decodeRunBundle`), runs the same analysis as the Analyze screen (`runMetrics` with the table
maximum, `survival`) and formats with the same helpers (`fmtMoney`, `fmtPct`, `fmtInt`, `fmtZ` from
`src/core/ui/results/format.ts`). `tests/build/static-pages.test.ts` checks that each page contains
the Analyze screen's own `verdictLine` for that run. The stake explanation ("How the stakes move")
is generated from the strategy definition following `docs/design/strategy.md` §7.4, and the
strategy's own notes are shown verbatim. Remaking the gallery bundles (see `gallery/README.md`)
updates the pages on the next build.

## Service worker

These files are left out of the precache list (`isStaticSiteFile` in `build/static-pages.ts`, used
by `build/vite-plugin-sw.ts`), and `src/pwa/sw.ts` does not intercept requests for them, so a
navigation to `strategies/<slug>/` always gets the real page from the network, never the app shell.
`tests/build/sw.test.ts` covers both.

## Head, JSON-LD and IndexNow

- `index.html` (the app shell) carries the title, description, canonical, Open Graph/Twitter tags,
  a `WebApplication` JSON-LD block and a `<noscript>` link to `strategies/`. JSON-LD is a data block,
  so the CSP (`script-src 'self'`) does not apply to it; `tests/build/csp.test.ts` allows it.
- Static pages carry `Article`/`LearningResource` (strategy) or `CollectionPage` (index) plus a
  `BreadcrumbList`, joined to the landing site's `https://creynia.com/#creynia` and
  `https://creynia.com/#website` ids. Their link-preview image is
  `https://creynia.com/assets/og/spinner.jpg`, owned by the landing repo.
- After a deploy from `main`, `.github/workflows/pages.yml` runs `scripts/indexnow.mjs`, which posts
  the sitemap URLs to IndexNow (best effort, `continue-on-error`).
