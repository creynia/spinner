# Static pages, sitemap and llms files (SEO)

The app uses hash routes (`#/analyze/<id>`), which search engines and LLM crawlers ignore. So the
normal build (`npm run build`, i.e. `dist/`) also writes plain, JS-free HTML pages at real paths,
each with a link into the app. They are generated by `build/static-pages.ts` (the
`spinner-static-pages` Vite plugin, build only; the dev server does not serve them), which also
calls `build/static-research.ts` for the research and sources pages. Both share the page template
in `build/static-shell.ts` (head tags, JSON-LD breadcrumb, header, footer, the "Related" block).

| Path (under `https://creynia.com/spinner/`) | What |
| --- | --- |
| `strategies/` | All gallery runs side by side, the house-edge explanation, CTA to `#/gallery` |
| `strategies/<slug>/` | One per gallery bundle (`<slug>` = file name minus `.spinner.json.gz`), in `gallery/order.json` order |
| `research/` | The Research screen as a page: what the research is, headline results, every chapter with its lead; CTA to `#/research` |
| `research/<chapter id>/` | One per chapter of `src/app/screens/Research/content.ts` (`start`, `edge`, `martingale`, …); CTA to `#/research?chapter=<id>`, the same route the app's chapter links use |
| `sources/` | The Sources screen (`src/app/sources.ts`), one anchor per source id; CTA to `#/sources` |
| `sitemap.xml` | The SPA root and every page above, absolute URLs, no `lastmod` |
| `llms.txt` | [llmstxt.org](https://llmstxt.org/) index of the app and the pages |
| `llms-full.txt` | The full text of every page as Markdown |

## Where the numbers come from

Nothing on a strategy page is typed in by hand. The plugin decodes each committed gallery bundle
(`decodeRunBundle`), runs the same analysis as the Analyze screen (`runMetrics` with the table
maximum, `survival`) and formats with the same helpers (`fmtMoney`, `fmtPct`, `fmtInt`, `fmtZ` from
`src/core/ui/results/format.ts`). `tests/build/static-pages.test.ts` checks that each page contains
the Analyze screen's own `verdictLine` for that run. The stake explanation ("How the stakes move")
is generated from the strategy definition following `docs/design/strategy.md` §7.4, and the
strategy's own notes are shown verbatim. Remaking the gallery bundles (see `gallery/README.md`)
updates the pages on the next build.

## Research and sources pages

A chapter page shows the chapter's own text verbatim (lead, body, takeaways and "The math" from
`content.ts`). Each chart becomes the table of the values it plots: the rows come from `data.json`
through the app's loader (`row`, `path` in `data.ts`), the predictions from the app's maths
(`ladder()` in `ladderMath.ts`, `SURVIVORS`/`capLoss` in `survivors.ts`), and the formatting matches
`kit.tsx` (`money`, `pct1`, `spins`). The build keeps its own copy of each chart's row list (for
example `PLACEMENTS`, the limits columns, the candidate order); `tests/build/static-research.test.ts`
checks every copy against the chart component's export, and pins headline numbers to `data.json`.
Remaking `data.json` (`npm run research:app-data`) updates the pages on the next build.

The `edge` chapter also carries an exact house-edge table (European, American and triple-zero, plus
la partage), computed from each bet's payout and pocket count; the test pins every cell to the
engine's `betEdge`.

## Search wording and related links

Titles and first paragraphs answer the questions people search for, from the same numbers:
"Roulette Betting Systems That Work?" (strategies index), "<System> Roulette Strategy Tested" with a
"Does <system> work in roulette?" answer (each strategy page), "Does the Martingale Work in
Roulette?" (`research/martingale/`) and "Roulette House Edge: European vs American"
(`research/edge/`).

Every static page ends with a "Related" block of 3 to 5 links. A strategy page links the research
chapters whose `dataKeys` draw that gallery run (or the `edge` chapter when none does), its preset
source on `sources/` (`PRESET_SOURCES`), and the indexes; a chapter page links the strategies it
draws, its neighbouring chapters and `sources/`. The test checks the count and that every link
resolves to an emitted page.

## Service worker

These files are left out of the precache list (`isStaticSiteFile` in `build/static-pages.ts`, used
by `build/vite-plugin-sw.ts`), and `src/pwa/sw.ts` does not intercept requests under `strategies/`,
`research/` or `sources/` (nor the sitemap and llms files), so a navigation to one of them always
gets the real page from the network, never the app shell. The app's own Research and Sources
screens are hash routes (`#/research`, `#/sources`) and never request those paths.
`tests/build/sw.test.ts` covers both.

## Head, JSON-LD and IndexNow

- `index.html` (the app shell) carries the title, description, canonical, Open Graph/Twitter tags,
  a `WebApplication` JSON-LD block and a `<noscript>` block linking `strategies/`, `research/`
(and its Martingale and house-edge chapters) and `sources/`. JSON-LD is a data block,
  so the CSP (`script-src 'self'`) does not apply to it; `tests/build/csp.test.ts` allows it.
- Static pages carry `Article`/`LearningResource` (strategy, research chapter), `CollectionPage`
  (the two indexes) or `WebPage` with `citation`s (sources), plus a `BreadcrumbList`, joined to the landing site's `https://creynia.com/#creynia` and
  `https://creynia.com/#website` ids. Their link-preview image is
  `https://creynia.com/assets/og/spinner.jpg`, owned by the landing repo.
- After a deploy from `main`, `.github/workflows/pages.yml` runs `scripts/indexnow.mjs`, which posts
  the sitemap URLs to IndexNow (best effort, `continue-on-error`).
