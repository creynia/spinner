# spinner: App & Repo Architecture

Status: design spike, ready for reconciliation into `decisions.md`.
Companion docs: `game.md` (roulette plugin), `strategy.md` (strategy language),
`harness-data-analysis.md` (seeds, workers, stores, metrics).

**What this doc owns:** the stack and every tooling config, the repo layout and
the import boundaries, the app shell (routes, screens, phone and desktop
layouts), the chart approach, PWA and service worker, CI and Pages, the
`src/core` extraction mechanics, file ownership and batons, and the work
packages. It does **not** own anything *inside* a module's contract: the types
in `src/core/contracts/*.ts` come from the three companion docs. Where this doc
and a companion disagree about a module's internals, the companion wins; where
they disagree about a path, a boundary, a tool or a WP, this doc wins;
`decisions.md` beats both.

**Baseline.** The sibling apps crappy, baccaratton and holdumb
(`/home/user/creynia/*`, read-only) share one stack and one set of configs.
spinner copies them unless a row in §1.2 says why not. Every config below was
**verified** in a scratch scaffold on 2026-10-28
(`/tmp/claude-0/-home-user-spinner/828ad1c6-cbad-5e73-b247-9a1c047fbf35/scratchpad/scaf`):

### 1.2 What differs from the siblings, and why

| Area | Siblings | spinner | Why |
|---|---|---|---|
| Version ranges | `^`/`~` ranges + lockfile | exact pins | four parallel agents and a future shared core; the lockfile is regenerated by WP0 only |
| Playwright | 1.56.1 (chromium-1194 there) | 1.63.0 | the browser preinstalled in *this* environment is chromium-1243 = Playwright 1.63.0 |
| `marked`, `yaml`, content plugin | yes | **dropped** | no lesson content (non-goal) |
| `vite-plugin-singlefile`, `build:single`, `finalize-single.mjs`, `release.yml` | yes | **dropped** | single-file build is a chip (decisions #9). Workers stay plain module workers (`worker.format: 'es'`), no inline/IIFE transport |
| `fake-indexeddb` | no | yes (dev) | `core/store` is IndexedDB-backed and tested in node |
| tsconfig | `app` + `node` | `base` + `app` + **`worker`** + `node` | the `worker` program compiles core, game and workers with `lib: WebWorker` and no DOM, so a `document` reference in pure code is a **type error**, not only a lint error (§2.1) |
| Layering lint | glob blocks per (layer, depth) | one **resolving** local rule | two-level hierarchy (core modules + games), path aliases, dynamic `import()`, re-exports and `new URL(…, import.meta.url)`: resolving the specifier to a path is shorter and cannot be escaped by depth (§4) |
| Path aliases | none (relative) | `@core`, `@core/*`, `@game/*`, `@app/*` | outside `src/core` everything reaches core by alias, so core can move to a submodule at the same path with zero import changes (§5) |
| E2E serving | `vite preview` at `/` | `vite preview --base /spinner/` | e2e runs under the same sub-path as Pages, so an absolute `/foo` URL bug fails in CI, not in production |
| E2E projects | mobile, phone-landscape, desktop | **phone-360**, phone, phone-landscape, desktop (+ `perf` opt-in) | playbook §12 requires 360 px |
| `test:e2e` | `playwright test` (webServer builds) | `npm run build && playwright test` (webServer only previews) | CI builds once and hands `dist` to e2e and perf as an artifact |
| CI | check, e2e | check, build, e2e, perf, gallery | §9 |
| SW precache | every file | every file **except gallery bundles** (cached on first open) | the gallery may be up to 20 MB |

### 2.3 Vite (`vite.config.ts`)

```ts
import { readFileSync } from 'node:fs';
import { defineConfig } from 'vite';
import preact from '@preact/preset-vite';
import { aliases } from './build/aliases.ts';
import { swPlugin } from './build/vite-plugin-sw.ts';
import { galleryPlugin } from './build/vite-plugin-gallery.ts';

const pkg = JSON.parse(readFileSync(new URL('./package.json', import.meta.url), 'utf8')) as {
  version: string;
};

export default defineConfig({
  // Relative base: dist works at https://creynia.github.io/spinner/, under any fork's path, and in
  // `vite preview --base /spinner/`. Hash routing means the document is always <base>index.html.
  base: './',
  define: {
    __APP_VERSION__: JSON.stringify(pkg.version),
    __BUILD_SHA__: JSON.stringify((process.env.GITHUB_SHA ?? 'dev').slice(0, 7)),
  },
  resolve: { alias: aliases },
  worker: { format: 'es' },
  plugins: [preact(), galleryPlugin(), swPlugin()],
  build: { target: 'es2022', outDir: 'dist' },
  preview: { port: Number(process.env.PORT ?? 4173), strictPort: true },
});
```

**Why `base: './'` is correct for `https://creynia.github.io/spinner/`.** All
routes are hash routes, so the browser only ever loads `/spinner/` (=
`/spinner/index.html`). `./assets/…` resolves to `/spinner/assets/…`; the
worker is created with `new URL('./sim.worker.ts', import.meta.url)`, which
Vite rewrites relative to the importing chunk; the SW is registered as
`./sw.js` and gets scope `/spinner/`; the manifest uses `start_url: "./"` and
`scope: "./"`. Same as the three siblings, all deployed under `/<repo>/`.
**Rule for code:** never build a URL from `'/'`; fetch app files with
`new URL('gallery/index.json', document.baseURI)` (main thread) or relative to
`import.meta.url`. The e2e suite runs under `/spinner/` to catch violations.
(The alternative, `base: '/spinner/'`, is correct too but breaks forks and
`vite preview` at `/`; see Open question 3.)

WP0 ships `swPlugin()` and `galleryPlugin()` as no-op stubs (`{ name }`) so the
config never changes after WP0; infra fills them in.

### 2.6 ESLint (`eslint.config.js`) with lint-enforced boundaries

The boundary rule is a **local plugin inside the config file** (no
dependency). It resolves every import specifier (relative at any depth, the
aliases, dynamic `import()`, `export … from`, and `new URL('…', import.meta.url)`)
to a repo path, classifies importer and target into zones, and checks the
matrix of §4. Verified with the cases in §4.3.

```js
import { dirname, relative, resolve, sep } from 'node:path';
import js from '@eslint/js';
import tseslint from 'typescript-eslint';
import prettier from 'eslint-config-prettier';
import globals from 'globals';

// ---- Layering (docs/design/architecture.md §4) -----------------------------------------------
// One local rule resolves every import specifier (relative at any depth, @core/@game/@app aliases,
// dynamic import(), re-exports, `new URL('…', import.meta.url)`) to a repo path, classifies the
// importer and the target into zones, and checks the allow matrix below. Resolving instead of
// globbing means a relative import cannot slip through by being deeper or by taking a detour.

const ROOT = import.meta.dirname;
const CORE_MODULES = [
  'contracts', 'money', 'rng', 'strategy', 'experiment', 'harness', 'store', 'analysis', 'ui',
];
/** Which core modules each core module may import (itself is always allowed). */
const CORE_ALLOWED = {
  contracts: [],
  money: ['contracts'],
  rng: ['contracts'],
  strategy: ['contracts', 'money', 'rng'],
  experiment: ['contracts', 'money', 'strategy'],
  harness: ['contracts', 'money', 'rng', 'strategy', 'experiment'],
  store: ['contracts', 'money', 'experiment'],
  analysis: ['contracts', 'money'],
  ui: ['contracts', 'money', 'rng', 'strategy', 'experiment', 'harness', 'store', 'analysis'],
  testing: ['contracts', 'money', 'rng', 'strategy', 'experiment', 'harness', 'store', 'analysis'],
};
/** Bare packages each zone may import (tests additionally get TEST_PACKAGES). */
const PREACT = ['preact', 'preact/hooks', 'preact/jsx-runtime'];
const TEST_PACKAGES = ['vitest', '@testing-library/preact', 'fake-indexeddb', 'fake-indexeddb/auto'];

/** Zone of a repo-relative posix path. */
function zoneOf(p) {
  let m;
  if (p === 'src/core/index.ts') return { zone: 'core', mod: 'index' };
  if ((m = /^src\/core\/([^/.]+)(\/|\.ts$|$)/.exec(p))) return { zone: 'core', mod: m[1] };
  if ((m = /^src\/game\/([^/]+)\/ui(\/|$)/.exec(p))) return { zone: 'game-ui', game: m[1] };
  if ((m = /^src\/game\/([^/]+)(\/|$)/.exec(p))) return { zone: 'game', game: m[1] };
  if (p.startsWith('src/workers/')) return { zone: 'workers' };
  if (p.startsWith('src/pwa/')) return { zone: 'pwa' };
  if (p.startsWith('src/app/')) return { zone: 'app' };
  return { zone: 'other' }; // tests/, build/, configs, anything outside src
}

function toRepoPath(spec, file) {
  const clean = spec.replace(/[?#].*$/, '');
  let abs;
  if (clean === '@core') abs = resolve(ROOT, 'src/core/index.ts');
  else if (clean.startsWith('@core/')) abs = resolve(ROOT, 'src/core', clean.slice(6));
  else if (clean.startsWith('@game/')) abs = resolve(ROOT, 'src/game', clean.slice(6));
  else if (clean.startsWith('@app/')) abs = resolve(ROOT, 'src/app', clean.slice(5));
  else if (clean.startsWith('.') || clean.startsWith('/')) abs = resolve(dirname(file), clean);
  else return null; // bare package
  return relative(ROOT, abs).split(sep).join('/');
}

/** Public entry points that code outside a module may import. */
function isPublicEntry(target, p) {
  const s = p.replace(/\/index(\.tsx?)?$/, '').replace(/\.tsx?$/, '');
  if (target.zone === 'core') {
    if (target.mod === 'contracts') return true; // type files, frozen
    return s === 'src/core' || s === `src/core/${target.mod}`;
  }
  if (target.zone === 'game') return s === `src/game/${target.game}`;
  if (target.zone === 'game-ui') return s === `src/game/${target.game}/ui`;
  if (target.zone === 'workers') return s === 'src/workers/spawn';
  return true;
}

/** Returns an error message, or null when `importer` may import `spec`. */
function check(file, spec) {
  const from = relative(ROOT, file).split(sep).join('/');
  const src = zoneOf(from);
  const isTest = /\.test\.tsx?$/.test(from) || from.includes('/__fixtures__/');
  const target = toRepoPath(spec, file);

  // Bare packages.
  if (target === null) {
    if (spec.startsWith('node:')) {
      return isTest || src.zone === 'other' ? null : `${from}: node built-ins only in tests/build.`;
    }
    if (src.zone === 'other' || src.zone === 'app') return null;
    if (isTest && TEST_PACKAGES.includes(spec)) return null;
    const ui =
      src.zone === 'game-ui' || src.zone === 'pwa' || (src.zone === 'core' && src.mod === 'ui');
    if (ui && PREACT.includes(spec)) return null;
    return `${from} may not import the package '${spec}' (only ${ui ? 'preact' : 'nothing'}; architecture.md §4).`;
  }

  const dst = zoneOf(target);
  const msg = (why) => `${from} → ${spec}: ${why} (architecture.md §4).`;
  // Inside a module: anything. Across modules: the public entry only.
  const sameModule =
    (src.zone === 'core' && dst.zone === 'core' && src.mod === dst.mod) ||
    (['game', 'game-ui'].includes(src.zone) && dst.zone === src.zone && src.game === dst.game) ||
    (src.zone === dst.zone && ['workers', 'pwa', 'app'].includes(src.zone));

  switch (src.zone) {
    case 'core': {
      if (dst.zone !== 'core') return msg('src/core imports nothing outside src/core');
      if (spec.startsWith('@')) return msg('inside src/core use relative imports (extractable)');
      if (sameModule) return null;
      if (dst.mod === 'index') return msg('src/core modules must not import the core barrel');
      const allowed = isTest
        ? [...CORE_MODULES, 'testing']
        : (CORE_ALLOWED[src.mod] ??
          (src.mod === 'index' ? CORE_MODULES.filter((m) => m !== 'ui') : []));
      if (!allowed.includes(dst.mod)) return msg(`core/${src.mod} may not import core/${dst.mod}`);
      return null;
    }
    case 'game':
    case 'game-ui': {
      if (sameModule) return null;
      if (src.zone === 'game-ui' && dst.zone === 'game' && dst.game === src.game) return null;
      if (dst.zone === 'core') {
        if (!spec.startsWith('@core')) return msg('reach src/core through @core/…');
        if (dst.mod === 'ui' && src.zone !== 'game-ui')
          return msg('only game ui may import core/ui');
        if (dst.mod === 'testing' && !isTest) return msg('core/testing is for tests');
        return isPublicEntry(dst, target) || isTest
          ? null
          : msg('import a core module entry, not a deep file');
      }
      return msg(`src/game/${src.game} may import only @core/* and itself`);
    }
    case 'workers': {
      if (sameModule) return null;
      if (dst.zone === 'core' && dst.mod !== 'ui')
        return isPublicEntry(dst, target) ? null : msg('deep import');
      if (dst.zone === 'game') return isPublicEntry(dst, target) ? null : msg('deep import');
      return msg('src/workers may import only non-UI core and game modules');
    }
    case 'pwa':
      return sameModule ? null : msg('src/pwa imports nothing app specific');
    case 'app': {
      if (sameModule) return null;
      if (dst.zone === 'core' && dst.mod === 'testing') return msg('core/testing is for tests');
      return isPublicEntry(dst, target) || isTest
        ? null
        : msg('import a public entry, not a deep file');
    }
    default:
      return null; // tests/, build/, configs: unrestricted
  }
}
```

Rules that follow from the layout:

- Every module directory has an `index.ts`; outside code imports **only** that
  entry (`@core/strategy`, `@game/roulette`, `@game/roulette/ui`). Deep imports
  are a lint error (tests excepted). `@core/contracts/*` files may be imported
  individually (they are types).
- Inside `src/core`, imports are **relative** (no aliases), so core compiles in
  any host that mounts it, with or without `paths`.
- `src/core/index.ts` re-exports the non-UI modules only; UI is `@core/ui`. The
  worker bundle therefore never contains Preact.
- `GameUi` (Preact component types) lives in `src/core/ui/game-ui.ts`, **not**

  composes `{ plugin: roulette, ui: rouletteUi }` in `src/app/services/game.ts`.
- The core harness never spawns workers itself: `createPool({ spawn, size })`
  takes `spawnSimWorker` (from `src/workers/spawn.ts`) injected by the app, so
  `src/core` has no `new URL(…)` pointing outside itself and tests inject the
  in-thread transport.
- The harness does not import the store: it writes through a `RunSink`
  interface in `contracts/run.ts` that `core/store` implements; the app wires
  them in `src/app/services/runs.ts`.

## 5. `src/core` extraction mechanics

Goal (PLAYBOOK §11): when the craps app starts, `src/core` moves to its own
repo (working name **`creynia/casino-lab-core`**) and is mounted back at the
**same path** as a git submodule. No import changes in either app.

### 5.1 Invariants kept from day one (all enforced)

1. Nothing in `src/core` imports outside `src/core` (lint, incl. tests).
2. Inside core, only relative imports (lint), so core needs no `paths`.
3. Core tests use `src/core/testing` (`coin`, a two-outcome fake plugin with a
   rational edge, implementing the full `GamePlugin` contract), never roulette.
4. Core fixtures live next to their module (`src/core/<m>/__fixtures__/`),
   never in `tests/fixtures`.
5. Core's only package is `preact` (in `core/ui`); its dev deps are a subset of
   the app's (vitest, happy-dom, @testing-library/preact, fake-indexeddb).
6. `src/core/README.md` documents the module map, the matrix of §4.2 and this
   section; `src/core/version.ts` holds `CORE_VERSION` (semver; bumps whenever
   a contract or any output that feeds run ids changes).
7. The host provides: the `@core` aliases (tsconfig `paths`, `build/aliases.ts`),
   Vitest including `src/core/**/*.test.*`, the worker entry and spawn, and the
   boundary rule (the rule's zone logic only needs `src/core/<module>`).

### 5.2 Steps (done once, by the orchestrator, when the second app starts)

```bash
# 1. In spinner: split core with history into a branch.
git subtree split --prefix=src/core -b core-split
# 2. Create creynia/casino-lab-core (public, MIT), push the branch as its main.
git push git@github.com:creynia/casino-lab-core.git core-split:main
# 3. In the core repo add: package.json (preact as peerDependency; the dev deps
#    of §1.1 that core uses), tsconfig.json (base + WebWorker program + app
#    program for core/ui), vitest.config.ts (node + dom projects), eslint.config.js
#    (the boundary rule with only the core zones), .github/workflows/ci.yml (check).
# 4. Back in spinner, on a branch:
git rm -r src/core && git commit -m "Move src/core to casino-lab-core"
git submodule add https://github.com/creynia/casino-lab-core.git src/core
git -C src/core checkout <pinned sha> && git add .gitmodules src/core
# 5. CI and Pages: actions/checkout with `submodules: true` (public repo: no token).
# 6. Every agent brief: `git submodule update --init` after creating a worktree.
```

Updating core afterwards: change it in the core repo by PR, then bump the
pinned SHA in each app by PR (`git -C src/core fetch && git -C src/core checkout
<sha>`). Each app's CI proves its pin. Core tests run in both the core repo CI
and each app's CI (Vitest includes `src/core/**`).

### 5.3 What else may move (decided by the audit spike, not now)

Candidates: the roulette and craps plugins (`src/game/<g>` is already
self-contained and reaches core only through `@core/*`), `src/workers`
(generic once it takes the plugin as a parameter), `src/pwa`, `build/*`,
`tests/e2e/helpers.ts`, and the configs of §2. Not shared: `src/app`, presets,
`gallery/`.

label), a sticky stepper at the bottom (|◀ ◀ ▶/❚❚ ▶ ▶|, speed). Phone
landscape: table left, trace right. Desktop ≥ 1200: three panes (table, trace,
state: layout, equity sparkline, vars, progression steps).

**Compare `#/compare?runs=…`.** Header chips for the runs (remove/add); a
note saying "paired by session (same seed)" or "Welch (different seeds)".

(runs as columns) beside the overlay chart.

**Sweep `#/sweep/:groupId`.** Metric selector; metric-vs-parameter line with

per-item actions (open, duplicate, export, delete with confirm); storage usage
per run and total, "Request persistent storage".

**Gallery, Import, Settings, More.** Simple lists/forms. Settings: theme,
money framing (per session / per hour / per 100 rounds, global), default pace
preset, storage (usage, persist, delete all with confirm), export all / import
all, **Check for updates**, About (app version, build SHA, core and game
versions, license, the decisions #11 disclaimer verbatim).

**Storage banner.** If IndexedDB is unavailable, blocked or full, a
dismissible banner: "Results are kept in memory only on this device. Export
runs to keep them." Everything still works in memory.

### 6.4 State and services (`src/app/services`, `src/app/state`)

- `services/game.ts`: `export const game = { plugin: roulette, ui: rouletteUi }`.
- `services/pool.ts`: one lazily created pool,
  `createPool({ spawn: spawnSimWorker, size: min(hardwareConcurrency − 1, 8) ≥ 1 })`.
- `services/db.ts`: opens the store (memory fallback), exposes `storageStatus`.
- `services/runs.ts`: `startRun(definition)`, `resumeRun(runId)`, `pauseRun`,
  `cancelRun`: wires the harness run controller to the store's `RunSink`;
  publishes progress to `state`.
- `services/quickCheck.ts`: 200 sessions through the same pool, nothing stored.
- `services/settings.ts`: settings in the IndexedDB `settings` store, with
  `theme` mirrored to `localStorage['spinner:theme']` (read synchronously in
  `main.tsx` to avoid a flash); every access in try/catch.
- `state/`: a ~50-line observable store (`get`, `set`, `subscribe`) plus
  `useStore(selector)` with an identity check, so screens re-render on change
  (crappy lesson: Preact skips identical children; selectors return new
  objects only on change).

### 6.5 Error handling

and mark the run `error` (harness doc). No `console.error` on any happy path
(e2e asserts none).

### 6.6 Accessibility

axe clean on every screen at every e2e viewport; charts have text summaries
and table fallbacks (§7); colour is never the only signal (red/black pockets
carry the number; won/lost carry text; rejected carries an icon and a label);
the BetPicker is a grid of real buttons with labels ("Split 17–20, $25").

## 7. Charts: hand-rolled SVG

Decision: **no chart dependency.** As in crappy (`ResultsHistogram`,
`BankrollChart`, `EdgeChart`), the shapes are few (histogram, fan band,
step curve, line with band, bars), every one needs a text summary and table
fallback anyway, and a library would be the largest thing in the bundle and in
the precache.

Structure (`src/core/ui/charts`, ui-charts WP):

- `geom/` (pure TS, node-tested): `linearScale`, `niceTicks(min, max, count)`,
  `formatMoney(cents, framing)` (delegates to `core/money`), `histogramRects`,
  `fanPaths(checkpoints, percentiles)`, `stepPath` (survival), `bandPath`,
  `barRects`. Inputs are the analysis outputs (typed arrays, quantile
  tables), never raw sessions.
- `ChartFrame`: `<figure>` → title, the SVG (`role="img"`,
  `aria-labelledby` title + summary), a one-sentence **summary** computed from
  the data ("Median ends at −$40; 90 % of sessions end between −$310 and
  +$180"), and `<details><summary>Data table</summary><table>…`.
- Components: `Histogram` (zero line and expected-net line marked, labelled),
  `FanChart` (p5–p95 outer band, p25–p75 inner band, median line, dashed
  analytic expected line), `SurvivalChart` (step), `LineBand` (convergence
  and sweep), `Bars` (breakdowns, horizontal on phones so labels fit),
  `OverlayHistogram` (compare: outlines, distinct dash patterns as well as
  colours), `Sparkline` (Watch equity).
- Sizing: `useElementWidth()` (ResizeObserver) measures the container; the
  chart lays out at real pixel width (tick count and label density depend on
  it), height from an aspect ratio with a minimum (phone 220 px). Text ≥ 12 px.
- Colours: tokens only (`--chart-1…6`, `--band-outer`, `--band-inner`,
  `--line-median`, `--line-expected`, `--zero`), defined for light and dark;
  validated for contrast by the ui-charts WP following the dataviz conventions
  (no meaning by colour alone, direct labels over legends where they fit).
- Performance: geometry memoized on input identity; live Run charts throttled
  to 4 Hz; a 10,000-session histogram or a 128-checkpoint fan renders in
  < 16 ms on desktop.
- Tests: geometry against hand-computed fixtures (node); components render
  the right number of marks and a non-empty summary and table (dom). E2E
  screenshots of the real thing (integration) built from real runs, never mock
  data.

## 9. Gallery plumbing (decisions #8)

- Bundles: `gallery/<slug>.spinner.json` or `.spinner.json.gz` (export format

## 11. File ownership and batons

### 11.1 Ownership

Every path belongs to exactly one WP (the `[…]` tags in §3). After a WP
merges, its paths stay owned by that WP's *area*; later fixes go to whichever
pool agent the orchestrator assigns, with the same ownership. Tests live with
their code and belong to the same owner. `tests/app/**` belongs to the owner
of the screen under test.

### 11.2 Batons (shared files; the orchestrator owns them)

`BATON REQUEST <path> <why>` → `BATON GRANTED` → push → `BATON RELEASE`.

| Path | Typical requester | Rule |
|---|---|---|
| `package.json`, `package-lock.json` | anyone | WP0 makes this unnecessary; orchestrator adds deps serially, regenerates the lock |
| `tsconfig*.json`, `build/aliases.ts` | core-harness (worker program), infra | |
| `eslint.config.js` (incl. `CORE_ALLOWED`) + `tests/build/layering.test.ts` | any core WP | an edge change edits both in one commit |
| `vite.config.ts`, `vitest.config.ts`, `playwright.config.ts` | infra, integration | WP0 already wires every plugin; edits should be one-liners |
| `index.html`, `src/env.d.ts` | infra, app-shell | |
| `src/core/contracts/*.ts`, `src/core/ui/game-ui.ts` | everyone | **frozen**; change proposed to main, relayed to all dependants via an update file |
| `src/core/index.ts`, `src/core/ui/index.ts`, `src/core/version.ts` | core WPs, ui WPs | append exports only; `CORE_VERSION` bumps by orchestrator |
| `src/app/main.tsx`, `src/app/routes.tsx` | app-shell, integration | WP0 makes routes complete; new routes only via main |
| `src/workers/spawn.ts` | core-harness | frozen after WP0 |
| `src/core/testing/**` | core-strategy, core-analysis, core-store | owned by core-harness after WP0; others request |
| `src/app/styles/tokens.css` | ui-charts, game-ui, ui-* | app-shell owns; chart and felt tokens by request |
| `docs/design/decisions.md`, `docs/chips.md`, `gallery/**` | anyone | orchestrator writes |

```
              ├─ app-shell ──────────────────────┘              │
              └─ infra (any time; gallery index after analysis+store) ┘
```

Queue the orchestrator hands out, next package to whichever agent frees up:

1. **Wave 1** (4 agents): game, core-strategy, core-harness, core-analysis
   (the long poles and everything's dependencies).
2. **Wave 2** (as wave-1 agents finish, interleaved with their reviews):
   core-store, app-shell, ui-charts, game-ui (once game has pushed the catalog).
3. **Wave 3**: ui-define (needs strategy + game merged), ui-results (needs
   analysis + store + harness + charts), ui-watch, infra.
4. **Wave 4**: integration (one agent; a second may join for the perf test
   and screenshots).

Critical path: WP0 → core-strategy → ui-define → integration, and WP0 →
core-harness → ui-results → integration. Early pushes that unblock
dependants (merged into their branches, not waited on as PRs): game's
`bets.ts` + `facts.ts`, core-strategy's `validate`, core-analysis's result
types (already in contracts), app-shell's kit.

Merge order: game → core-strategy → core-harness → core-analysis → core-store
→ app-shell → ui-charts → game-ui → infra → ui-define → ui-results → ui-watch
→ integration. After each merge, dependants merge `main` into their branch
(retargeting alone does not trigger CI).

Heavy commands on the 4-core box: one agent at a time runs `test:e2e` or
`test:perf`; Vitest is fine in parallel.
